# 매출·매입 금액 조회 권한의 실제 응답 확인

2026-09-23 조사, 9월24일 후속. 사용자의 진행 위임에 따라 권한 없는 금액을 숨기는 방향을 작업 기준으로 삼았다. 선택지에 대한 별도 명시 답변으로 기록하지 않는다. 초기 진단은 제품 변경 없이 진행했으며, 이후 기존 사용자 저장의 권한 보존 패치를 로컬에 적용했다(AMOUNT_PERMISSION_SAVE_FIX_20260924.md). 운영 사용자 권한·DB·서비스 변경 없음.

## 확인한 동작

현재 공식 시험 API에서 일반 User 계정의 `Amount.ViewSales`, `Amount.ViewPurchase` 유무와 무관하게 같은 담당지점 전표 목록·상세가 총액/단가/행 금액을 반환한다. 권한 이름과 실제 금액 제한 동작의 관계를 확정해야 한다. 사용자가 모든 직원의 금액 조회를 허용하는 정책인지, 미허용 사용자에게 금액을 숨겨야 하는지 질문한 상태다.

| 합성 계정의 금액 권한 | 매출 상세 | 매입 상세 | 목록 |
| --- | --- | --- | --- |
| 두 권한 없음 | 200, 총액/단가 123200 | 200, 총액/단가 456500 | 두 전표 금액 반환 |
| 매출만 있음 | 동일 | 동일 | 동일 |
| 매입만 있음 | 동일 | 동일 | 동일 |
| 다른 담당지점, 두 권한 없음 | 404 | 404 | 빈 목록 |

미로그인 상세 조회는 401이었다. 일반 계정의 Role=User와 로그인 응답의 두 금액 권한 조합을 확인한 뒤 시험했다. 위 표의 권한은 금액 권한만을 뜻한다. 초기화기가 별도의 편집·렌탈 권한을 추가하는 기존 동작은 그대로 두었고 실제 운영 계정의 권한은 조회하거나 바꾸지 않았다.

## 범위 및 근거

## 첫 시험의 중단과 재시험

첫 시험은 초기화 전 부여한 권한 목록이 로그인 후에도 전체적으로 같아야 한다는 시험 전제에서 중단했다. 초기화기가 다른 기본 역할 권한을 추가했기 때문이다. 금액 권한은 추가되지 않았다. 첫 결과/스크립트/로그는 보존했다.

두 번째 시험은 관심 대상인 두 금액 권한 조합과 일반 역할을 명시적으로 검사했다. 4계정의 목록·상세 12개 관찰 및 미인증 1개 대조를 완료했다. 정상 응답을 얻기 위한 업무 HTTP 요청 재시도는 없었다. 소유 프로세스 종료 요청으로 exitCode=1이므로 정상 애플리케이션 종료 시험으로 해석하지 않는다. 종료와 포트 닫힘을 확인했고 원본 PC DB·공식 시험 DB/DLL·Git index는 시작 전 해시와 같다.

## 2026-09-24 운영 영향과 수정 전제

진행 위임 이후 사전 영향 점검을 계속했다. 중앙 인증 DB에서 READ ONLY 트랜잭션·5초 statement_timeout으로 활성 계정 수와 두 권한 보유 여부만 집계했다. 계정명·암호·업무 행은 출력하지 않았다. 활성4개 중 Admin3개, 일반1개였으며 그 일반 계정에는 두 금액 권한이 모두 없었다. 계정 권한을 바꾸거나 실제 운영 계정으로 금액 노출을 시험한 것은 아니다. 격리 API에서 재현된 문제와 운영 계정의 권한 구성이 함께 존재하므로 단순 마스킹의 업무 영향이 실제로 발생할 수 있다.

추가로 EnvironmentSettingsViewModel.SaveUserAsync는 신규/기존 사용자 모두 BuildPermissionsForRole 결과를 전송한다. 일반 역할 기본 목록에도 두 금액 권한이 들어 있다. 따라서 현재 코드를 그대로 두면 관리자 화면의 기존 사용자 저장 시 미보유 금액 권한이 다시 부여될 수 있다는 코드 경로를 확인했다. 실제 운영 계정 저장으로 재현하지 않았다. 조회 응답만 수정해 끝낼 수 없는 이유다.

### 적용해야 할 변경 단위

1. 서버가 판정하는 금액 가시성 상태를 계약에 명시하고, 실제0원과 미공개를 구분한다. 기존 클라이언트에는 미공개 값을 정상 금액처럼 내려보내지 않도록 버전 호환 처리가 필요하다.
2. 전표/품목/가격등급/수금·지급/렌탈·정산/잔액과 출력·첨부의 읽기 경로를 각각 분류한다. 기존 tenant/office 범위는 유지하고 공유 품목의 수량 조회·판매 가능 범위와 원본 수정 권한을 분리한다.
3. 미공개 금액을 포함한 DTO 재전송이 원래 금액을 덮지 않게 서버 저장을 검증한다. 미전송 전표/행/수금이 있으면 해당 원본과 outbox를 보존하고 무조건 삭제하거나0원으로 치환하지 않는다.
4. PC/모바일의 목록·상세·편집·인쇄·PDF·엑셀 및 권한 회수/계정 전환/오프라인 캐시를 함께 처리한다. 기존 사용자 저장에서 제한한 두 권한을 자동 재부여하는 경로도 수정해야 한다.
5. 양쪽 권한 없음/매출만/매입만/둘다/Admin, 다른 업체·지점, 권한 변경 전후·재로그인·오프라인 및 dirty 재전송을 격리 검증한다. 허용된 비금액 변경 후 서버 원금액 보존과 무권한 금액 변경 거부를 별도 검사한다.

**사전점검 판정:** 집계·진단·설계 기록은 진행 가능. 현재 계약 그대로의0원 마스킹 및 운영 적용은 데이터 훼손/호환성 위험 때문에 보류한다. 아직 제품 수정이나 금액 제한 적용을 완료한 상태가 아니다. 1.1.743 후보의 기존 설치/UI 증거는 유지하되 전체 권한 점검 완료본으로 발행하지 않는다.
