# 제한 계정 편집·SQLite·실제 HTTP 동기화 통합 증거

## 확인 범위

기존 화면 모델 시험과 서버 API 시험 사이의 연결을 검증했다. 임의의 새 임시 폴더에 API 실행 파일을 복사하고 loopback 포트와 새 SQLite DB를 사용했다. Invoice.Edit만 가진 시험 계정은 새 임의 비밀번호로 생성하며 비밀번호/토큰은 출력하지 않는다. 원본 업무 자료 및 운영 서버는 변경하지 않았다.

실제 SalesViewModel로 품목/수량3/비고/메모를 작성하고 정상 저장 경로를 호출했다. 로컬 SQLite는 비공개 상태와 dirty를 보존했다. 실제 SyncService와 ErpApiClient가 Kestrel API에 금액 null을 전송했고 서버가 단가1,100원/합계3,300원을 계산했다. 시험 중 성공 응답을 한 번 유실시켜 같은 mutation으로 재시도하도록 했으며 정상 완료됐다.

서버에서 다시 받은 비공개 전표를 편집 모델에 불러와 수량4와 비고/메모를 수정하고 재동기화했다. 관리자 조회는4,400원, 제한 계정 전송 및 로컬 표시 계약은 계속 null이었다. 추가 동기화 후 revision은 변하지 않았다. 실제 서버 DB 전표 건수가 전송된 고유 전표 ID 수와 일치해 중복 생성이 없었다. SQLite 재연결 후에도 수량4/수정 메모/비공개/dirty 해제 및 전표 outbox 승인 시각을 확인했다.
