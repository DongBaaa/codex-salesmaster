# 청구 프로필 저장 시 기존 자산 설치 장소 보존

## 문제와 수정

최신 3DB 전체 복원 자료를 현재 공식 PC DLL로 재현했다. `2412-009`를 중부수도사업소 청구 프로필에 추가할 때 기존 16대의 `InstallSiteName`이 요금팀·유수율제고팀·소장실 등의 원래 값에서 거래처명으로 바뀌었다. 프로필 금액은 의도대로 1,287,000원 → 1,463,000원이 됐고 청구 이력은 유지됐으나 다른 자산의 설치 장소 보존 조건을 위반했다.

`RentalStateService.SyncBillingProfileAssetsAsync`에서 자산의 기존 설치 장소를 우선 사용하도록 수정했다. 기존 값이 비었을 때의 거래처명·프로필 설치 장소·설치 위치 보충 순서는 유지했다. 자산/품목 소유권, 테넌트, 지점, 청구 금액 계산과 접근 권한은 변경하지 않았다. 운영 업무 자료에는 적용하지 않았다.

- 같은 실제 자료의 격리 로컬 시험에서 기존 16대의 업무 필드 변경이 16건 → 0건으로 감소했다. 9개 기존 청구 항목(배열 순서 및 생략된 null 표현 차이는 허용), 기존 청구 이력 2건, 마지막 청구일 2026-08-31 보존.
- 원본 PC DB SHA-256 보존. 고객/품목/관리업체 등 다른 테이블에 서비스 저장으로 인한 변경 없음. 선택 자산과 해당 프로필·연결 이력에 한정된 업무 필드 변경 확인.
- 앱 저장 4회(프로필 저장, 자산 저장, 각 반복 저장)와 컴파일된 관리업체 중복 정규화 단계 통과.

현재 시험 입력은 최신 전체 복원에서 가져온 자산 302개·프로필 60개·거래처 156개·연결 이력 2,024개와 같은 스냅샷 지문으로 검증한 품목 2,598개·관리업체 4개다. 원본 PC 복사본의 여섯 렌탈 테이블을 시험용으로 구성했으며 기타 로컬 테이블은 원본 사본 상태다. 원본 pending/outbox를 정리한 것이 아니며 이 시험 DB를 운영 또는 원본 PC에 덮어쓰면 안 된다.
