# 품목 편집 화면의 비공개 가격 상태 — 2026-09-24

## 변경과 영향

품목·등급의 비공개 금액 계약을 PC 품목/재고 관리 화면에 연결했다. 금액 조회 권한이 있어도 현재 품목 가격을 받지 못했다면 `비공개`로 표시하고 읽기 전용으로 둔다. 알려진 실제 0원과는 구별한다. 재고자산 금액도 비공개 매입 단가로 계산하지 않는다.

- 품목 선택, 편집 스냅샷 복원, 자동저장, 계속 입력 등록에 매입/매출 비공개 상태를 전달한다.
- 등급 행마다 비공개 상태를 보존하고 편집기 바인딩과 저장 변환에 적용한다. 비공개 등급의 저장용 0이 알려진 품목 기본 등급 가격을 덮어쓰지 않게 한다.
- 계속 입력으로 새 품목을 만들 때 비공개 등급 행을 새 0원 등급으로 생성하지 않는다. 알려진 값과 비금액 항목은 기존 흐름을 따른다.
- 편집 중 목록 새로고침에서 가격이 비공개로 바뀌면 작성한 비고·수량을 유지하면서 가격 표시를 차단한다. 검색 때문에 편집 품목이 목록에서 빠진 경우도 포함한다. 이후 전체 품목 재조회로 실제 가격을 받기 전에는 오래된 초안을 공개 가격으로 취급하지 않는다.
- 기존 단가 입력 스타일과 `비공개` 변환기를 재사용했다. 업체/지점·자산 소유 범위, 재고 이동·청구 정책과 비금액 저장 권한은 바꾸지 않는다. 서버 응답 마스킹·프로토콜·운영 DB는 이번 변경에서 활성화하거나 수정하지 않는다.

## 검증

신규 재현 10건에서 모두 실패를 확인한 뒤 수정했다. 초기 집중 검사 57건이 통과했다. 추가한 새로고침/검색 편집 보존 6건을 포함한 최종 회귀, 공식 테스트 앱 실행·정상 종료·백업, 원본 DB/HEAD/index 보존 결과는 `D:\DevCaches\tradeplan-inventory-hidden-state-20260924\verification.json`과 TRX에 기록한다.

신규 검사는 방향별 비공개/실제 0, 가격 입력 거부, 재고자산 금액, 실제 저장된 비고·기존 기본 등급 가격·dirty 상태, 스냅샷 복원·새 품목 연속 입력, WPF 표시/읽기 전용 전환, 필터로 가려진 편집 유지와 조회만으로 저장되지 않는 동작을 확인한다.

최종 코드의 PC 회귀 1,747건과 보존 검사 27건·고정 해시 선언 형식 1건이 통과했다. 공식 실행환경의 앱 DLL은 회귀 검사 DLL과 해시가 일치한다. 오른쪽 모니터의 공식 테스트 앱에서 2,080개 품목 조회, 기존 단가 및 실제 0원 등급 표시, 등급 셀 편집기 폭을 확인했다. 값은 변경하지 않았다. 동기화 완료 표시 후 정상 종료(exit 0)했고 서버 SQLite `quick_check=ok`, sidecar 0을 확인했다. 제한 계정 전체 업무의 네이티브 화면 검증은 아직 미완료다.

## 남은 범위

이 화면 수정만으로 전체 금액 보호가 끝나지 않는다. 전표 품목 선택·계산, 나머지 진단/비교/복구 소비자, dirty Pull와 충돌 재시도, 새 프로토콜/구버전 차단과 서버 품목·등급·렌탈·Transaction 응답 마스킹, 제한 계정의 실제 업무·기기·출력 검증이 남아 있다. 원래 거래플랜/워크플랜 전체 Goal과 업무 자료 정합성·운영/패키지/Git 검증 범위를 유지한다.
