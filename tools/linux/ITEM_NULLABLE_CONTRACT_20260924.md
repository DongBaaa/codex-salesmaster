# 품목·등급 비공개 금액 계약 및 저장 보호 — 2026-09-24

## 변경

품목 가격 6개와 품목 등급 단가가 비공개 값(null)을 수신·보관·재전송할 수 있도록 변경했다. 기존 형식에서 생략된 가격은 이전과 같이 0원으로 읽으며, 명시적인 null은 비공개로 구별한다. 서버가 비공개 품목/등급 응답을 보내는 기능은 아직 활성화하지 않았다.

- PC는 매입/매출 방향별 숨김 상태와 등급 단가 숨김 상태를 별도 열로 보관한다. 비공개 가격의 로컬 숫자 값은 0으로 비우고 숨김 상태를 함께 기록하며, 다시 전송할 때 null로 복원한다. 부분적으로 비공개인 매출 가격 집합은 전체 매출 가격을 비공개로 취급한다.
- 기존 DB에는 기본값 false의 상태 열 3개를 추가한다. 기존 가격은 바꾸지 않는다. 공개된 실제 0원을 다시 수신하면 숨김 상태가 해제된다.
- 서버의 품목/등급 Apply는 null 가격을 덮어쓰지 않는다. 명시적인 0원은 기존 권한 규칙에 따라 저장할 수 있다. 품목 저장·동일 명령 재전송에서 비금액 메모와 서버 가격을 보존한다.
- PC 품목 편집기가 숨김 상태를 복사하지 않아도 저장 직전 DB의 상태를 유지한다. 관리자도 아직 수신하지 않은 가격을 0원으로 저장하지 않는다. 비공개 등급 행은 빈 편집 목록 때문에 삭제하지 않고, 알 수 없는 가격으로 새 등급을 만들지 않는다.
- 모바일은 원본 null을 편집 시 0으로 대체하지 않고 비공개로 표시한다. 전표 품목의 가격은 매입/매출 방향을 구별한다. 기본 단가 해석과 편집 화면도 null을 수용한다.

## 아직 필요한 작업

이번 변경은 서버 응답 마스킹의 선행 데이터 계약 작업이다. PC의 나머지 가격 표시·계산·진단·복구 소비자, dirty Pull 및 충돌 재시도에서 숨김 상태를 사용하는지 추가 검증해야 한다. 새 프로토콜과 `/items` 구버전 차단, 품목/등급 성공·재전송·Pull·충돌 응답 마스킹, 렌탈 금액과 구조화 JSON, Transaction Pull도 남아 있다. 이전 진단에서 확인한 응답 노출이 이번 변경만으로 모두 해결된 것은 아니다.

제한 계정의 전체 실제 업무·실기기·출력, 기존 업무 자료 정합성, 워크플랜 및 복원 등 전체 Goal 범위를 유지한다. 통합 수정 확정 전 운영 배포·버전 게시·commit·push를 수행하지 않는다.
