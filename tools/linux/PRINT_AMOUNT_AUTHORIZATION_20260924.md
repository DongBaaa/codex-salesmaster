# 전표 출력의 금액 조회 권한 재확인

## 범위와 영향

사전 점검 결과, 기존 출력 권한 콜백은 로그인·업체/지점·거래처 접근만 확인했다. 따라서 금액 조회 권한이 없거나 비공개로 갱신된 전표의 기존 출력물도 허용될 수 있었다. 해당 출력물에는 가격·수금·합계가 포함되므로 로컬 수정 진행 가능으로 판단했다.

`LocalStateService.PrintAuthorization.cs`에서 매출/수금 전표는 매출 금액 권한, 매입/발주/경비 전표는 매입 금액 권한을 확인한다. 전표 또는 활성 행의 금액이 비공개인 경우에도 출력을 허용하지 않는다. 삭제된 비공개 행은 제외하고, 알 수 없는 전표 종류는 허용하지 않는다. 별도 읽기 전용 DB 연결로 커밋된 상태를 재조회하므로 이미 열린 미리보기와 최종 인쇄/PDF/XPS 저장에도 기존 출력 권한 감시가 적용된다.

업체·지점·자산·품목 조회 및 원본 수정 규칙은 변경하지 않는다. 이 콜백은 출력에만 쓰이며 품목·수량·비고의 전표 저장 경로를 변경하지 않는다. 금액 없는 출력물까지 별도 허용하는 정책은 이번에 구현하지 않았고, 기존 전표 출력 진입점에는 같은 검사가 적용된다.

## 남은 작업

서버 읽기 응답 마스킹, 고객 잔액·다른 금액 DTO·출력/첨부 경로 전체, 계정/권한 변경 시 오프라인 캐시 보호, 제한 계정 실제 저장·동기화, 구형 클라이언트 업데이트 및 새 설치 패키지 검증은 아직 남아 있다. 이번 변경으로 전체 금액 권한 기능 완료를 주장하지 않는다. 운영 배포·commit·push는 수행하지 않는다.

다음 출력 점검은 `RentalAssetViewModel`, `RentalContractEditorViewModel`, 진단/집계 Excel 및 별도 `StatementPrintService` 호출 경로를 포함해야 한다. 이번 콜백은 메인 전표 인쇄와 판매 창의 출력물 편집/매출/매입/발주/세금계산서에 연결되어 있지만 모든 문서 생성기의 공통 보호를 뜻하지 않는다.

원본 PC DB와 HEAD는 직전 검증에서 그대로였고, 현재 스테이징 항목 목록은 직전 체크포인트와 일치했다. 그보다 이전 인덱스 파일 해시 변경은 원인이 확정되지 않았으며 인덱스를 덮어쓰지 않았다.
