# 전표·렌탈 정산의 비공개 금액 보호

개별 전표와 렌탈 청구의 합계·수금누계·잔액을 nullable로 표현한다. 매출/매입 금액 조회 권한과 실제 금액의 공개 여부를 확인하며, 없는 자료나 범위 밖 자료도 실제0원으로 반환하지 않는다. 확인 불가한 정산의 완료·수금 상태는 ‘비공개’로 표시한다.

수금창은 비공개 잔액으로 자동 금액을 제안하거나 초과금액을 계산하지 않는다. 조회 예외 때 원시 캐시 금액으로 되돌아가 재계산하던 경로도 제거했다. 비공개 연결 전표·청구 증거를 이용하는 로컬 정산 저장은 거부한다. 일반 수금은 기존 Payment.Edit 권한으로 직접 금액을 입력해 저장할 수 있다. 전표 품목·수량·비고 저장 및 서버 금액 계산 정책은 유지한다.

렌탈 정산 조회는 청구회차와 실제 업체·지점 범위의 비공개 증거를 판정한다. 삭제된 거래나 다른 회차·다른 업체의 증거 때문에 현재 정산을 숨기지 않는다. 공개된 잔액이 실제0원이면 0원으로 유지한다.

## 검사 중 발견한 조회 회귀

기존 렌탈 자동 집계에 추가됐던 비공개 확인용 별도 조회 때문에 24회차 조회9회 제한이11회, 청크 경계12회 제한이14회, 501건 Pull50회 제한이54회로 실패했다. 시험 기대값은 유지하고 기존 프로필 조회에 비공개 증거의 존재 검사를 함께 포함했다. 첫 경로 수정 후 Pull52회가 남아 재계산 경로도 같은 방식으로 수정했다. 원래 비공개 자료를 보존하는 조건은 유지한다.

최종 시험 수와 공식 앱/백업 검증은 `D:\DevCaches\tradeplan-settlement-privacy-20260924\verification.json`에 기록한다. 최초 실패 결과도 같은 폴더에 보존한다.

수금 이력과 입력창 전체의 현재 권한 표시, 다른 금액 DTO와 모바일, 제한 계정 네이티브 UI 전체 업무, 패키지/운영 반영 검증은 계속 남아 있다. 거래 Pull 마스킹은 아직 비활성이다. 운영 데이터·서비스·기존 Git index·HEAD를 변경하지 않는다. 전체 Goal은 완료되지 않았다.
