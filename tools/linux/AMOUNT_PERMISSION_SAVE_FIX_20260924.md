# 기존 사용자 저장 시 금액 조회 제한 보존

2026-09-24. 금액 권한 통합 수정 중 사용자 저장 경로의 로컬 수정이다. 금액 조회/동기화 응답의 노출 문제를 해결한 것으로 간주하지 않는다.

## 문제와 변경

환경설정에서 기존 일반 사용자 이름 등 정보를 저장하면 BuildPermissionsForRole이 매출·매입 금액 권한을 기본값으로 다시 부여했다. 두 권한 없음/매출만/매입만 계정의 제한이 저장 요청에서 사라졌다.

사용자 선택 또는 서버의 확정 저장 응답을 편집기에 반영할 때 두 금액 권한을 사용자 ID와 함께 복사한다. 기존 일반 사용자 저장에서는 이 값만 보존하고, 새 사용자와 명시적인 관리자 승격은 기존 기본 권한 구성을 유지한다. 권한 목록이 누락됐거나 편집 대상 ID와 스냅샷 ID가 다르면 재조회 안내 후 요청을 보내지 않는다. 최신 사용자 정보를 선택하면 이전 권한 스냅샷을 교체한다.

## 사전 영향도와 한계

- 진행 가능 범위: 사용자 편집 요청의 두 금액 권한 보존. 자산·품목·청구/전표·거래처 조회 쿼리, 수량/요금, 업체·지점 범위, dirty/outbox는 변경하지 않는다.
- ITWORLD/USENET/YEONSU 기본 비금액 권한 구성은 유지한다. 모든 종류의 기존 사용자 권한을 보존하도록 확장한 패치는 아니다.
- 실제 운영 사용자 권한/DB/서비스 변경 없음. 운영 사용자 목록은 기존 보호된 읽기 전용 내보내기 도구로 집계/스냅샷만 수집했다.
- 금액 응답·캐시·출력·저장 계약의 통합 수정은 여전히 필요하다. 이 패치로 금액이 숨겨지는 것은 아니다.

## 검증

- 수정 전 실제 SaveUserCommand와 HTTP 요청 직렬화 경로를 사용한13개 검사: 실패10/통과3. 세 지점의 제한된 권한 조합9개에서 자동 재부여, ID 불일치1개에서 요청 전송을 재현했다.
- 수정 후 환경설정 관련106개 검사 전체 통과, 건너뜀0. 서버 HTTP 응답은 시험 핸들러, 로컬 저장소는 격리된 메모리 SQLite다. 실제 운영 HTTP 저장 시험이 아니다.
- 신규17개 사례: 세 지점×네 권한 조합의 연속2회 저장, 신규 계정 초기화, 관리자 승격, 잘못된 사용자 ID, 누락된 권한 목록, 새로 불러온 권한 회수.
- 각 지점 검사에서 tenant/office/scope 보존 및 품목·전표 편집의 기존 기본 권한도 확인했다. 이 검사는 자산/품목/전표의 모든 실제 업무 화면 시험을 대체하지 않는다.
- Release 빌드 및 최초104개 통과 후 누락 응답/권한 회수2개를 보완하고 최종106개를 다시 통과했다.

증거: `D:\DevCaches\tradeplan-amount-permission-save-20260924`의 before-fix.trx, after-fix.trx, final-fix.trx, 로그 및 변경 전 소스 사본.

## 공식 시험/발행 상태

공식 준비 스크립트를 Release로 실행하고 정상 완료했다. 기존 검증된 격리 AppData를 유지하는 SkipDataCopy를 사용했으므로 최신 원본 DB 전체를 재복사한 시험은 아니다. 권한 스냅샷은 새로 읽었고, 암호 초기화는 격리 시험 계정에만 적용했다. 준비 중 리비전 충돌86건이 로그에 나타났으나 최종 준비 작업은 exit0/runtime_ready=True로 완료됐다. 원본 업무 자료의 충돌이 해결됐다는 뜻은 아니다.

Run-All.cmd 실제 실행에서 admin 시험 자동 로그인과 메인 화면을 확인했다. 처음 왼쪽에 열린 창을 화면 도구로 오른쪽으로 이동한 뒤 정상 종료했다. 첫 이동은 창 밖 좌표 오류로 적용되지 않아 재관찰 후 창 안 좌표로 이동했다. 오른쪽 이동 후 일부 화면이 잘려 이번 화면 검증을 환경설정의 실제 저장 조작 완료로 확대하지 않는다. 사용자 저장 요청/권한 조합 검증은 위106개 자동 검사 증거다.

RuntimeLogs/Run-All.log에서 앱 PID1624 exitCode0, 소유 API PID35872 정리, SQLite sidecar0 및 최종 DB 해시를 확인했다. 래퍼도 exit0이었고 창/실행 프로세스가 남지 않았다. 자동 종료 백업 `거래플랜_20260924_034948_237.gpbackup`이 생성됐다. 수정된 공식 App DLL은 빌드 DLL과 SHA256 `C0ADA7CAE9785E9BF95A757CCB5D1046CEEA1511DDD8A6976A65E40BE92A1DE4`로 일치했다. 실행파일 host EXE 해시만으로 코드 반영 여부를 판정하지 않았다.

메인 화면에서 운영 점검 오류0·주의181·참고5를 관찰했다. 이는 전체 업무 자료가 정상이라는 판정이 아니며 기존 계약/청구/미전송 자료 확인 항목은 유지한다. 원본 PC DB와 원본 Git index 해시는 이전 기준과 일치했다. 공식 시험 DB는 의도적으로 재시드됐으므로 불변으로 보고하지 않는다.

기존 1.1.743 설치 후보는 이번 패치를 포함하지 않는다. 금액 권한 통합 수정과 공식 검증 이후 버전/패키지 갱신이 필요하다. 사용자 수락·live·commit·push 및 전체 Goal 완료를 선언하지 않는다.
