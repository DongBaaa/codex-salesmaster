# 금액 조회 제한 계정의 전표 서버 계산

## 확정 기준과 적용 범위

사용자 결정: **품목·수량·비고 저장 허용, 금액은 서버가 계산**.

이번 변경은 이 기준의 서버 저장 경로를 구현한다. 매출 또는 매입 금액 권한이 없을 때 일반 전표 생성/수정과 동기화 전표 생성/수정에서 요청 금액을 신뢰하지 않는다. 조회 응답, 데스크톱/모바일 표시·캐시·출력의 금액 숨김은 아직 구현 중이며 이 변경만으로 금액 접근 제어가 완성되지 않는다.

운영 반영, 계정 권한 변경, 운영 DB 수정, 설치 후보 재생성, Git commit/push는 수행하지 않는다. 기존 1.1.743 설치 후보는 이번 변경 이전의 산출물이다.

## 사전 영향도

- 청구/전표: 금액 권한에 따라 서버에서 단가·행 금액·합계를 계산한다. 기존 전표의 거래처·종류·부가세 방식 변경은 제한 계정에 허용하지 않는다.
- 품목: 기존 품목 읽기 범위를 사용하고 품목 원본을 수정하지 않는다. 수령 이력으로 접근 가능한 타 지점 소유 품목의 판매도 검증한다.
- 업체/지점: 기존 고객·전표·품목 쓰기/읽기 범위 검증을 유지한다. 최근 매입 이력은 전표 조회 범위 내에서만 선택한다.
- 자산/렌탈: 자산 마스터 변경 없음. 기존 렌탈 링크·정산·버전 보호 규칙을 우회하지 않는다. 자동 가격 근거가 없는 신규 자유 입력/렌탈 요금 행은 현재 단계에서 제한 계정의 저장이 거부될 수 있다.
- 동기화/dirty: 서버 가격으로 DTO가 정규화되어도 영수증에는 원래 요청 해시를 보존한다. 같은 요청의 재전송은 가격이 바뀌었어도 재계산하지 않고, 같은 mutation ID로 수량을 바꾼 재전송은 거부한다. 원본 PC dirty/outbox 자료는 변경하지 않는다.

판정: 로컬 구현 및 격리 시험 진행 가능. 금액 응답/캐시 통합과 실제 제한 계정 화면 검증 전 운영 배포 불가.

## 계산 규칙

1. 금액 권한이 있으면 기존 금액 입력 동작을 유지한다. 다른 방향의 금액 권한만 보유한 경우에는 서버 계산을 적용한다.
2. 기존 행의 품목 식별·단위가 같으면 저장된 단가를 유지한다. 수량까지 같으면 기존 할인 행 금액도 보존한다. 수량 변경 시 저장된 단가 × 새 수량으로 계산한다.
3. 품목·수량이 바뀌지 않은 수정은 기존 합계/공급가/부가세를 보존한다. 과거 합계를 이번 패치에서 임의 정정하지 않는다.
4. 데스크톱 수정 버전은 새 행 ID를 만들므로, 같은 범위의 이전 버전에서 품목 식별값이 유일하게 일치하는 행만 연결한다. 서로 다른 기존 행이 중복되어 판별할 수 없으면 저장을 거부한다.
5. 신규 매출 행은 거래처 품목별 사용자 단가 → 단가 등급의 설정된 가격 열/기존 A·B·C·소매 규칙 → 매출단가/소매단가 순으로 결정한다.
6. 신규 매입 계열 행은 해당 거래처의 조회 가능한 최근 매입 전표 단가 → 품목 매입단가 → 매출단가/소매단가 순으로 결정한다. 모바일과 데스크톱에서 기존 계산 방식이 달랐으므로 이 서버 규칙을 클라이언트에 연결하는 후속 작업이 필요하다.
7. 등록 품목 없음, 단위 불일치, 적용 단가 없음, 충돌하는 등급 설정, DB 금액 범위 초과는 원인을 안내하고 전표 저장을 거부한다. 0원으로 추정하지 않는다. 새 계산값은 DB의 소수 2자리 기준으로 반올림한다.

새 행이 기존 행보다 먼저 오는 경우에도 기존 행 ID의 단가를 빼앗지 않도록 연결을 예약한다. 추가 시험에서 새 행을 EF가 기존 행 수정으로 추적하여 저장 충돌을 일으키는 경로도 발견했다. 일반 수정과 동기화 수정 양쪽에서 기존에 없던 행 ID는 명시적으로 Added로 등록한다.

- 수정 전 핵심 시험 10개: 8개 실패/2개 통과. 요청의 2원 단가가 저장되거나 기존 단가가 0원으로 지워지는 문제 재현.
- 수정 후 핵심 시험과 확장: 최종 관련 검사 **464개 통과, 0개 실패, PostgreSQL 전용 3개 미실행** (`final4.trx`). 전체 데스크톱·모바일 회귀 완료를 의미하지 않는다. 중간 `final3.trx`의 신규 행 저장 2개 실패도 보존했다.
- 최종 서버 전체 검사: **1,735개 통과, 0개 실패, PostgreSQL 전용 24개 미실행** (`server-all.trx`). 이 집계에는 위 관련 검사도 포함되므로 통과 수를 합산하지 않는다.
