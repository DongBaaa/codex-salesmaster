# 비공개 금액의 정합성 검사 보류 — 2026-09-24

## 범위와 사전 판단
- 이전 v48은 휴지통 비공개 금액 복원 수정 및 공식 PC 검증을 완료한 진척이다. 전체 Goal은 미완료다.
- 진행 가능: 운영점검 서비스에서 전표/수금/거래/렌탈 정산의 비공개 상태를 보존한다. 실제 금액, 업체·지점 접근 범위, dirty/outbox, 운영 서비스는 변경하지 않는다.
- 금액을 못 보는 직원도 품목·수량·비고를 저장하고 금액은 서버가 계산한다는 사용자 정책을 유지한다. 이번 변경은 로컬 진단이 비공개 자료를 0원으로 오해하지 않도록 하는 작업이다.

## 재현과 수정
- 첫 SQLite 격리 시험 21건 중 15건 실패. 비공개 전표/품목 금액을 비교한 허위 합계 오류, 비공개 수금과 거래의 금액 불일치 오판, 렌탈 정산/미수금 요약 오판 및 비공개 내부 값의 진단 문자열 노출을 확인했다.
- 전표 진단용 projection에 AmountsHidden을 전달한다. 품목/수금 합계는 알려진 0원과 일부 행의 비공개 때문에 계산할 수 없는 합계를 구별한다. 삭제된 비공개 행은 현재 합계에 영향을 주지 않는다.
- 금액을 검증할 수 없는 항목은 `amount_verification_deferred` 참고 알림으로 표시한다. 오류 수정 동작을 연결하지 않으며, 금액 검증 완료로 취급하지 않는다.
- 거래와 수금의 금액은 양쪽이 모두 공개됐을 때 비교한다. 비공개 거래만으로 수금 행이 반드시 있어야 한다고 추정하지 않는다. 확인 가능한 잘못된 전표 연결은 계속 보고한다.
- 렌탈 run 정산 및 프로필 요약은 실제 합산에 필요한 거래/직접 결제가 비공개인 경우 보류한다. 동일 ID 거래에 이미 포함된 수금은 이중 합산하지 않으며, 그 중복 수금의 비공개 상태만으로 알려진 거래 근거를 무효화하지 않는다.
- 비공개 내부 값은 합산 과정에서도 제외한다. 숨겨진 큰 값이 있어도 정산 합산에 사용하거나 오버플로를 발생시키지 않도록 시험한다.
- 삭제 전표의 활성 수금, 삭제 수금의 잘못된 거래 연결, 거래 scope 불일치 같은 구조 진단은 유지하고 비공개 금액 문자열은 `비공개`로 표시한다.
- v48의 연결 전표 복원 재조회는 이미 확인한 전표 ID를 보존해 nullable 경고를 없앴다. 연결 대상이나 복원 정책은 바꾸지 않는다.
