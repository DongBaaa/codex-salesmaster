# 렌탈 수정 대기 자료의 금액 비공개 상태 반영

## 범위와 변경

렌탈 자산·청구 프로필·배치 이력·청구 기록의 Pull 처리에서, 로컬 수정 대기(IsDirty) 자료는 서버가 금액을 비공개로 내려주더라도 기존 공개 상태를 유지했다. 수정 중인 업무 정보와 금액 원본을 덮어쓰지 않고 각 비공개 플래그를 추가 반영하도록 수정했다.

- 자산의 매입/매출 비공개 상태는 각각 독립적으로 반영한다.
- 로컬 메모, 계약/연결 정보, 금액 원본, Revision, IsDirty는 유지한다.
- 이후 공개 금액을 받더라도 아직 확인되지 않은 로컬 수정 금액을 다시 공개하지 않는다. 수정 대기가 없는 자료는 서버 값을 정상 반영한다.
- 기존 DTO 변환과 outbox 비교를 통해 숫자 금액, 보증금 텍스트, 초과 단가가 null인 새 전송 요청을 생성한다. 이전 실패 요청과 MutationId가 달라지는지 실제 HTTP 클라이언트 경로를 모의 수신해 검사한다.
- 업체/지점, 자산 식별값 중복 충돌, 청구 프로필 키 중복 충돌 및 관련 삭제 보류 규칙은 변경하지 않았다.

수정 파일: `Desktop/거래플랜.Desktop.App/Services/SyncService.cs`, `Tests/GeoraePlan.Desktop.App.Tests/HiddenRentalSyncTests.cs`. 테스트 빌드 변경에 따른 파일 해시 manifest와 고정 해시도 갱신했다.

## 남은 위험과 운영 반영 조건

이 수정만으로 렌탈 전체 금액 비공개가 완성되지는 않는다. **운영 서버의 렌탈 응답 마스킹은 아직 활성화하지 않았다.**

1. BillingTemplateJson/BillingRunsJson의 내부 UnitPrice/Amount/BilledAmount/SettledAmount는 아직 비공개 변환을 적용하지 않았다. 현재 PC 내부 모델은 non-nullable decimal이므로, null을 보내면 템플릿 기본값 대체 또는 실행 이력 파싱 실패가 발생할 수 있다. JSON의 품목·수량·비고·이력 식별자·삭제 이력을 보존하는 nullable 계약, 파서, 계산, 표시, 저장 정책을 함께 보완해야 한다.
2. 이 테스트의 청구 JSON은 금액이 없는 메타데이터 샘플이다. 중첩 JSON의 금액 유출 방지를 검증했다고 해석하면 안 된다.
3. PC 렌탈 화면·출력·계산 전체의 비공개 플래그 적용, 서버 저장 권한과 신규 금액 미확정 자료 처리, 프로토콜 호환성 및 Android 실제 사용 검증이 남았다.
4. 실제 사용자 PC DB, 운영 DB, RT 서비스는 변경하지 않는다. 설치 패키지·운영 배포·commit/push는 통합 검증 완료 전 보류한다.

사용자가 정한 전표 정책인 ‘품목·수량·비고 저장 허용, 금액은 서버가 계산’은 그대로 유지한다.
