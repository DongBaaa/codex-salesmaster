# 미수·미지급 상세 금액 권한 보호

## 재현 및 영향
- 공식 테스트 바이너리로 합성 잔액12,345원을 표시한 뒤 AmountViewSales를 회수해도 합계·선택 행·처리금액 입력값이 남는 것을 재현했다. 실제 DB를 열지 않았다.
- 수정 범위는 거래플랜 미수·미지급 상세 조회와 이 창의 단건/일괄 수금·지급이다. 지점/업체/자산/품목 소유권, 전표 품목·수량·비고 저장 및 서버 계산 정책은 유지한다.

## 변경 내용
- 행 금액과 거래처 합계를 nullable로 만들고 비공개를 실제0원과 구분한다. 숨겨진 전표를 잔액0으로 간주해 목록에서 제외하지 않는다.
- 현재 매출/매입 조회 권한으로 표시를 결정하고, 권한 변경 때 목록·선택·입력값·상태 문구를 초기화한다. 토큰만 갱신할 때는 유지한다.
- 조회 시작 시 접근 상태와 조회 버전을 캡처하여 권한 변경/재부여/창 종료 이후의 늦은 조회를 버린다. 저장 후 표시도 이전 권한의 금액을 다시 노출하지 않도록 검사한다.
- 단건/일괄 처리 전 현재 PaymentEdit 및 해당 금액 조회 권한과 선택 행의 공개 상태를 검사한다. 기존 저장 계층의 범위/비공개 정산 검사를 유지한다.
- 원본 전표 요약에 연결된 활성 비공개 수금/지급이 있으면 잔액은 알 수 없는 값으로 취급한다. 삭제된 연결 거래는 제외한다. 상관 EXISTS를 사용해 추가 왕복 조회를 만들지 않는다.
- 창 종료와 창 열기 실패 시 이벤트 구독을 해제한다.
- 비공개 표시 문자열을 사용하더라도 금액 열의 SortMemberPath는 실제 숫자 속성으로 유지한다.
