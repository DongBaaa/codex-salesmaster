# 전표 품목 목록의 비공개 단가 표시 — 2026-09-25

전표 하단 품목 목록의 매출단가·소매단가·A/B/C 단가에 품목 자체의 SalesAmountsHidden 조건을 연결했다. 사용자에게 조회 권한이 있어도 해당 품목의 가격을 받지 못했다면 비공개로 표시한다. 실제 0원은 0으로 유지하며, 매입 화면에서도 매출 단가 목록에는 매출 조회 권한을 적용한다.

화면 구성·스타일 및 품목/수량/비고 입력과 저장, 자산/업체/지점/거래처 조회 범위, 동기화/dirty와 서버·모바일 로직은 변경하지 않았다. 실제 XAML의 TextBlock 스타일과 바인딩을 읽어 WPF 논리 트리에서 검증한다. 레이아웃 전용 BasedOn 리소스만 제거하며 실제 표시/트리거는 그대로 실행한다. 창을 표시하지 않는 검사라 사용자 모니터를 건드리지 않는다.

수정 전 신규 11건 중 비공개 가격 10건이 실패하고 권한 변경 1건은 통과했다. 수정 후 단가 선택 검사를 포함한 집중 31건 통과. 잔존 가격 98,765 및 저장용 0, 알려진 0 및 12,345, 행 재바인딩, 권한 해제/복구, 다른 로그인 세션, dirty/원값 보존을 검증했다. 최종 관련 회귀 1,793건, 보존 검사 27건 및 선언 형식 1건 통과. 공식 앱의 오른쪽 모니터에서 기존 전표 55,000원과 하단 5개 단가 셀의 실제 0 및 매출 2,200,000/소매 2,600,000 표시를 확인한 뒤 변경 없이 정상 종료(exit 0)했다. 비공개/권한 변경은 실제 XAML 자동 검사로 검증했고, 제한 계정 전체 네이티브 흐름은 아직 미검증이다. 실행 파일 해시·백업·원본 DB/Git 보존은 해당 evidence의 verification.json에 기록한다.

금액 권한 통합 범위는 아직 미완료다. dirty Pull/충돌 및 서버 품목/등급/렌탈/Transaction 응답 마스킹과 프로토콜, 제한 계정 실제 업무·기기·출력, 패키지/운영/Git 검증과 원래 거래플랜·워크플랜 전체 Goal이 남았다. 운영 배포는 이번 단계에 포함하지 않는다.
