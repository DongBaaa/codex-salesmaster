# 수금·지급 비공개 금액 기반 보호 검증

## 적용 범위

사용자가 승인한 전표 품목·수량·비고 저장 및 서버 금액 계산 정책의 후속 보호다. TransactionDto의 13개 금액은 null을 비공개로 구분하고, 기존 금액 공개 응답과 구형 누락 필드의 0원 기본값은 보존한다. 직렬화가 null을 생략하지 않도록 했다. SQLite는 별도 AmountsHidden 열을 보존하며, 숨겨진 금액의 내부 0원 자리값은 전송할 때 모두 null로 복원한다.

서버는 하나라도 미공개인 활성 거래 저장을 거부하고, 삭제는 서버의 기존 금액을 보존하거나 없는 행을 삭제 완료로 승인한다. LocalStateService도 미공개 거래 저장을 거부한다. 비공개 거래의 결제 미러·렌탈 요약 계산을 건너뛰고, 공개 Payment만으로 숨겨진 거래의 채널별 금액을 채우지 않는다. 모바일 렌탈 이력은 미공개 거래를 제외하지 않고 금액 비공개로 표시하며, 비공개 활성 거래 초안 저장을 거부한다.

업체·지점/자산/품목/전표 접근 권한과 운영 데이터는 변경하지 않았다. 이번에는 거래 조회 응답의 금액 마스킹을 활성화하지 않았다. 나머지 잔액·합계 화면과 현재 권한/캐시 보호까지 마친 뒤 전환해야 한다.

- 원래 줄바꿈을 복원한 최종 빌드 후 서버 새 시험 28건, Desktop 새 시험 7건+해시·배포·출력 27건 재확인. 중복 실행 수를 합산하지 않는다. 최종 보관 목록 276항목 검증.

- 초기 컴파일 오류와 로컬 시험 실패는 보존했다. nullable 호출부와 nullable bool 단언을 수정했고, 시험 DB 경로를 명시하고 받아온 행의 IsDirty=false를 명시했다. 원본 PC DB/HEAD/기존 인덱스 항목은 그대로다.
- 공식 테스트 준비·Run-All과 정상 종료 백업, SQLite quick_check 및 앱/서버 바이너리 해시 일치를 확인했다. 제한 계정의 전체 실제 창 업무 검증을 완료했다는 뜻은 아니다.
