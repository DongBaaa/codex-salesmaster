# 수금 이력과 수정 입력의 금액 보호 — 최종 검증

수금 이력 표를 nullable 금액을 사용하는 표시 모델로 바꿨다. 현재 매출/매입 조회 권한, 연결 전표 종류, 저장된 비공개 여부를 확인한다. 비공개 금액은 ‘비공개’, 실제 0원은 0원으로 표시한다. 혼합 방향 내역과 알 수 없는 거래 종류는 양쪽 금액 권한이 없으면 공개하지 않는다. 기존 거래 구분명·메모 표시 방식은 유지한다.

수정창은 선택 행의 캐시 금액을 복사하지 않고 현재 업체·지점 범위에서 내역을 다시 읽는다. 권한이나 비공개 상태가 달라지면 이전 입력을 지우고 저장을 막는다. 권한 변경 또는 새 입력 후 늦게 도착한 조회 결과는 적용하지 않는다. 토큰만 갱신되면 기존 입력은 유지한다.

저장 서비스도 기존 비공개 상태를 확인한다. 새 객체에 같은 ID를 넣거나 비공개 표시를 false로 바꿔도 저장된 비공개 금액을 덮어쓸 수 없다. 내부 저장 경로는 삭제된 내역까지 확인하며, 삭제된 공개 내역도 일반 저장으로 되살릴 수 없다.

Payment.Edit 권한으로 직접 금액을 입력하는 일반 수금 신규 저장, 전표 품목·수량·비고 저장 및 서버 금액 계산 정책은 유지한다. 자산/품목 권한과 업체·지점 경계를 변경하지 않는다.

## 검증 증거

- 최종 회귀 623건 통과. 신규 보호 검사 33건 포함. 중간 620건과 표시 보완 후 82건은 중복 검사이며 합산하지 않는다.
- 파일 보호 확장 175건 통과. 최종 실행 파일 기준으로 기존과 같은 정확한 27건을 다시 실행해 통과했다. 보관 목록의 파일/디렉터리/소스 276항목 해시·크기를 검증했다.
- 최종 빌드 경고 0·오류 0. 공식 테스트 앱/서버 DLL과 현재 빌드 DLL이 일치한다.
- 오른쪽 모니터의 공식 테스트 앱에서 수금 이력 55,000원·지급 0원과 연결 정산 잔액 0원을 확인했다. 최근 이력 수정 불러오기로 통장수금 55,000원을 확인한 뒤 수정 취소로 입력을 비웠다. 업무 금액 입력·저장은 하지 않았다.
- Run-All 정상 종료 코드 0, 종료 백업 CRC 정상, 서버 SQLite quick_check=ok, 잔여 저널 0개, 테스트 포트 19080 종료를 확인했다.
- 원본 업무 DB 해시, HEAD, 기존 Git 인덱스 항목 보존을 검증한다. 통합 증거: `D:\DevCaches\tradeplan-payment-history-privacy-20260924\verification.json`.

최초 551건 중 1건이 삭제된 비공개 내역 조회 누락으로 실패해 수정했다. 보관 검사 중 빌드 1회는 파일 잠금으로 중단됐으며, 검사가 정상 종료된 뒤 최종 빌드·회귀 검사를 통과했다. 마지막 검사 선택식에 불필요한 릴리즈 검사들이 포함된 실행은 중단했고, 모든 276항목이 그대로인 것을 확인한 후 이전 통과 기록의 정확한 검사 이름으로 재검증했다. 실패/중단 기록은 같은 증거 폴더에 보존한다.

## 확인된 후속 결함과 미완료 범위

별도 진단 프로그램으로 공식 테스트 DLL에 합성 데이터만 넣어, 거래처 미리보기의 금액 권한 취소 후에도 미리보기와 기존 목록 행에 12,345가 남는 문제를 재현했다. 실제 AmountViewSales=false였으며 업무 DB는 열지 않았다. 이는 네이티브 화면 직접 재현과 구분한다. DLL 해시와 결과: `preview-revocation-reproduction.json`, 재현 프로그램: `preview-probe`.

후속으로 메인/거래처 목록과 미리보기의 현재 권한, 기존 행·입력 제거, 늦은 조회 응답, 금액 조건 검색과 요약을 수정·검증해야 한다. 다른 금액 DTO/렌탈/모바일, 제한 계정 실제 화면, 신규 패키지와 운영/Git 반영도 남아 있다. 거래 Pull 금액 마스킹은 아직 비활성이다. 현재 화면 검증은 관리자 시험 계정 기준이다. 운영 변경·commit·push 없이 전체 Goal을 유지한다.
