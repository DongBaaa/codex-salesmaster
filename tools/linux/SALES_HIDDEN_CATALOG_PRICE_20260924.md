# 전표의 비공개 품목 단가 처리 — 2026-09-24

## 변경과 영향

전표의 품목 단가 선택에서 비공개 값을 실제 0원·누락된 등급과 구별한다. 사용자 정책은 금액 제한 직원도 품목·수량·비고를 저장하며 금액은 서버에서 계산하는 것이다.

- 등급 단가 캐시에 비공개 상태를 보존하고, 비공개 등급을 기본 단가로 대체하지 않는다. 알려진 0원 등급의 기존 기본가 선택 규칙은 유지한다.
- 매입 단가가 비공개이면 판매가로 대신 계산하지 않는다. 알려진 매입 단가가 0원일 때 판매가를 사용하는 기존 경로는 매출 금액 권한 및 공개 상태를 확인한다.
- 비공개 가격으로 새 행을 추가하거나 기존 행의 품목을 바꾸면 수량·비고를 유지하고 금액을 null로 직렬화한다. 검색 문자열로 자동 연결되는 품목도 확인한다.
- 기존 전표 행을 다시 선택하면 그 행 자체의 공개 단가를 사용한다. 현재 품목 가격이 비공개라는 이유로 기존 전표 가격을 새로 계산하지 않는다.
- 품목/재고·권한의 수동 또는 자동 새로고침은 작성 중인 단가·수량·비고를 덮어쓰지 않는다. 가격을 더 이상 공개할 수 없으면 표시를 차단하고, 이후 공개 자료가 도착해도 옛 초안을 자동으로 다시 노출하지 않는다. 사용자가 품목을 다시 선택하면 최신 단가를 적용한다.
- 자산 조회, 품목 소유, 업체/지점, 거래처 선택 범위와 재고/청구 정책은 변경하지 않는다. 서버·모바일 소스와 운영 DB도 이번 변경에서 변경하지 않는다.

## 남은 작업과 적용 경계

품목/등급 서버 응답 마스킹은 아직 활성화하지 않았다. 현재 서버는 전표 금액 권한이 없는 계정의 null 금액을 계산하지만, 금액 권한이 있는 계정이 비공개 상태의 전표를 보내면 재조회 오류를 반환한다. 따라서 이번 클라이언트 변경만으로 권한 변경 직후의 모든 저장 흐름이 완성됐다고 볼 수 없다. 새 프로토콜·구버전 차단·서버 응답/재전송·dirty Pull와 충돌, 렌탈/Transaction 금액 계약, 제한 계정 실제 화면·기기·출력 및 설치/운영/Git 검증을 이어간다. 거래플랜·워크플랜 전체 Goal은 미완료다.
